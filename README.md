# Безопасный маршрут — Платформа управления AMR и АРМ Оператора

Программно-аппаратный комплекс для автономного мобильного робота (AMR) и автоматизированного рабочего места (АРМ) оператора в рамках соревновательного кейса «Безопасный маршрут» (`amr-sim 0.2`, схема `amr-1.0`).

Комплекс решает задачу автономной транспортировки грузов складской тележкой между доками (`warehouse`, `shop_a`, `shop_b`, `charger`) в экстремальных условиях: полная потеря сигналов спутников ГНСС, нулевая видимость в тумане, ложные лидарные эхо от метели, перекрытые проезды и активный трафик пешеходов.

---

## 1. Архитектура решения

Комплекс состоит из трех ключевых подсистем:

```
amrsim-safe-route/
├── backend/               # Боевой контроллер платформы (Python >= 3.10, только numpy)
│   ├── controller.py      # Оркестратор: конвейер обработки и интерфейс step(obs)
│   ├── geom.py            # 2D вычислительная геометрия, raycast, проекции, полигоны
│   ├── localize.py        # Локализация: EKF, скан-матчинг стен (Гаусс-Ньютон), dock-snap
│   ├── perceive.py        # Восприятие: фильтр снега/тумана, кластеризация, трекинг людей
│   ├── route.py           # Планирование: Pure Pursuit, латеральный объезд, локальный A*
│   ├── safety.py          # Предиктивная безопасность: TTC-модель, гувернер скорости, estop
│   ├── APPROACH.md        # Архитектурное описание подхода (Критерий О1)
│   └── scenarios/         # Валидационные сценарии команды (s1–s5)
├── frontend/              # АРМ Оператора (React 19, TypeScript, Tailwind CSS, Canvas 2D)
│   ├── src/components/    # Карта Canvas 2D, Header, рендерер формул Latex (KaTeX)
│   ├── src/pages/         # Dashboard, Replay Studio, Episodes, Missions, Analytics, Runner
│   ├── src/api/client.ts  # Server-Driven UI API-клиент с бесшовным статическим фоллбэком
│   └── src/__tests__/     # Модульные тесты интерфейса и логики (Vitest, 46 тестов)
├── scripts/
│   ├── server.py          # SDUI HTTP-сервер (REST API, стриминг логов, экспорт CSV/JSON)
│   └── eval.py            # Полный бенчмарк-раннер для пакета сценариев
└── tests/                 # Модульные тесты бэкенда (pytest, 163 теста)
```

## 2. Ключевые инженерные решения

### Бэкенд-контроллер (`backend/`)
- **Изоляция песочницы**: контроллер строго использует только стандартную библиотеку Python и `numpy` (версия $\ge$ 1.24.0). Никаких внешних зависимостей (`scipy`, `amrsim`, `threading` запрещены).
- **Скан-матчинг без ГНСС**: при пропадании спутникового сигнала (сценарий `02_gnss_shadow`, 143 м без ГНСС) курсор робота удерживается с точностью до 0.08 м за счет проецирования лучей лидара на векторные стены склада методом Гаусса-Ньютона.
- **Интеллектуальное взаимодействие с пешеходами**:
  - Оценка вектора скорости и курса человека через экспоненциальное сглаживание в базисе одометрии.
  - Предиктивная модель Time-To-Collision (TTC) с упреждающим замедлением с дистанции до 8.0 м.
  - Заблаговременная полная остановка ($v = 0$) на расстоянии 3.5–4.5 м при пересекающихся курсах: робот уступает дорогу пешеходу, не провоцируя его замирание (в симуляторе внимательный пешеход не останавливается, если робот неподвижен).
  - Широкий латеральный объезд стоящих пешеходов с боковым зазором $\ge 4.2$ м.
- **Фильтрация снега и тумана**: статистическое отсечение изолированных ложных отражений лидара с сохранением плотных кластеров препятствий.

### АРМ Оператора (`frontend/`)
- **Server-Driven UI**: динамическая загрузка готовых View Model с бэкенда (`/api/ui/*`) с автоматическим отказоустойчивым переключением на локальные данные, если сервер не запущен.
- **Интерактивная Canvas 2D карта**: аппаратный рендеринг геометрии площадки, лидарных лучей, позы робота, пешеходов и зон безопасности. Автоматическая подгонка `fit-to-bounds` на дашборде.
- **Replay Studio**: пошаговое и непрерывное воспроизведение телеметрии через `requestAnimationFrame` с честным масштабированием скоростей 0.1x, 0.5x, 1x, 2x, 5x, 10x.
- **Типографика формул KaTeX (LaTeX)**: строгое математическое оформление целевой функции и всех 6 блоков регламента соревнований ($S_{\text{del}}, S_{\text{eff}}, S_{\text{safe}}, S_{\text{rules}}, S_{\text{pose}}, S_{\text{col}}$).

## 4. Запуск и тестирование

### Проверка изоляции контроллера
```bash
python -m amrsim check backend
```
*Требование: 0 violations, 0 warnings, result: OK.*

### Модульные тесты бэкенда (163 теста)
```bash
pytest tests/
```
Для запуска отдельного набора:
```bash
pytest tests/test_controller.py
pytest tests/test_safety.py
```

### Модульные тесты фронтенда (46 тестов)
```bash
cd frontend && npm test
```

### Сборка фронтенда для продакшена
```bash
cd frontend && npm run build
```

### Запуск полного стека (SDUI Сервер + АРМ Оператора)
1. Запуск SDUI бэкенда:
   ```bash
   python scripts/server.py --port 8000
   ```
2. Запуск фронтенда оператора:
   ```bash
   cd frontend && npm run dev
   ```
   Интерфейс доступен по адресу `http://localhost:3000`.
