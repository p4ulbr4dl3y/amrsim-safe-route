# Безопасный маршрут - контроллер платформы Dreamteam 4.0

Автономная навигация мобильной платформы межцеховой логистики в условиях потери спутникового сигнала (тень ГНСС), атмосферных помех (туман, снег) и динамических препятствий.

- **Контроллер участника**: пакет [`team_dreamteam_4_0/`](team_dreamteam_4_0/) (только стандартная библиотека Python и NumPy).
- **Схема обмена**: контракт `amr-1.0` (`v`, `w`, `status`, `pose_est`, `note`).
- **Живой демо-стенд АРМ (О3)**: **https://state3407.space/amr/** (плеер тиков, карта 2D Canvas, разбор инцидентов, запуск симуляций).
- **Интерактивная документация API АРМ**: **https://state3407.space/amr/docs**.

---

## Быстрая проверка за 60 секунд (Quickstart)

Запуск верификации любым удобным способом:

```bash
# Способ 1: через Make (автоматически выбирает uv или стандартный python3):
make verify          # проверка изоляции Т3, модульные тесты Т5 и линтер
make sim             # запуск симуляции контрольного сценария 01_clear

# Способ 2: стандартный pip и venv (без uv):
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
PYTHONPATH=amrsim-participants python -m amrsim check team_dreamteam_4_0
pytest -v

# Способ 3: через менеджер uv:
uv sync
PYTHONPATH=amrsim-participants uv run python -m amrsim check team_dreamteam_4_0
uv run pytest -v
```

Веб-станция оператора АРМ (критерий О3):
- онлайн без установки: **https://state3407.space/amr/**;
- локальный запуск: `make arm` или `python arm/server.py --port 8000`.

## 1. Проверка изоляции и окружения (Критерий Т3)

По регламенту соревнований контроллер не использует внешних библиотек оптимизации, сетевых вызовов и записи на диск во время работы:
- версия Python >= 3.10;
- единственная зависимость: `numpy>=1.24.0` в корневом [`requirements.txt`](requirements.txt) и в [`team_dreamteam_4_0/requirements.txt`](team_dreamteam_4_0/requirements.txt).

Подготовка окружения:
```bash
uv sync
```
*Либо через стандартный pip: `python -m venv .venv && source .venv/bin/activate && pip install -r requirements-dev.txt`.*

### Валидация правил изоляции пакета команды:
```bash
PYTHONPATH=amrsim-participants uv run python -m amrsim check team_dreamteam_4_0
```
Ожидаемый результат:
```text
check team_dreamteam_4_0: 0 violation(s) or error(s), 0 warning(s)
result: OK
```

## 3. Честность оценки позы и алгоритмы (Критерии Т4, Т5, О1)

Архитектура контроллера разбита на изолированные модули в [`team_dreamteam_4_0/`](team_dreamteam_4_0/):

- **Локализация ([`localize/`](team_dreamteam_4_0/localize/))**:
  - покадровое сопоставление сканов со стенами методом **Левенберга-Марквардта** с функцией потерь Хубера (устраняет сингулярность гессиана у плоских стен, среднее время 0.8 мс на такт);
  - стробирование ГНСС: инновационный гейт 1.5 м, ограничение веса $k \le 0.15$; координаты спутника **никогда не копируются** напрямую в `pose_est`;
  - прецизионная привязка к геометрии дока (`dock-snap`);
  - при потере ориентации: переход в защитный статус `lost`, остановка платформы ($v = 0$) и двухуровневый поиск позы Coarse-to-Fine.
- **Восприятие ([`perceive/`](team_dreamteam_4_0/perceive/))**:
  - евклидова кластеризация точек лидара, фильтрация атмосферных помех (снег, туман);
  - сопровождение объектов одиночным фильтром Калмана Constant Velocity с пороговой эвристикой фиксации неподвижности;
  - детекторы расхождения карты `map_missing` (снесенные стены) и `map_extra` (неучтенные препятствия).
- **Планирование и траектория ([`route/`](team_dreamteam_4_0/route/))**:
  - чистое преследование Pure Pursuit с кривизно-оптимальным ограничением скорости ($a_{lat} \le 0.85$ м/с²);
  - латеральный сдвиг траектории для объезда локальных препятствий;
  - локальный репланнер A* по двухмерной сетке при блокировке коридора.
- **Безопасность ([`safety/`](team_dreamteam_4_0/safety/))**:
  - супервизор зазоров: ступенчатые пороги скорости ($d < 3.3$ м $\implies v \le 0.22$ м/с; $d < 0.8$ м $\implies v = 0$);
  - геометрический коридор торможения по сырому лидару;
  - защитный аварийный останов estop при критическом сокращении дистанции.

Инженерное обоснование выбора методов, математический аппарат и анализ альтернатив приведены в документах [`APPROACH.md`](APPROACH.md) и [`results/ALTERNATIVES.md`](results/ALTERNATIVES.md).

## 5. Автоматизированное рабочее место оператора (Критерий О3)

Веб-станция оператора предоставляет полный инструментарий мониторинга и анализа инцидентов по регламенту критерия О3:
- **Интерактивный плеер тиков**: визуализация 2D-карты предприятия на HTML5 Canvas, истинное положение платформы, оценка позы `pose_est`, пешеходы, сырой лидарный скан и шлейф пути;
- **Журнал инцидентов**: фильтрация штрафных эпизодов, переход к проблемному такту по клику, экспорт отчета в CSV;
- **Журнал рейсов**: контроль статусов миссий, времени прибытия и точности докования;
- **Запуск симуляций**: старт прогона сценария из веб-интерфейса через серверный runner с отображением результатов.

### Локальный запуск АРМ (1 команда):
```bash
python arm/server.py --port 8000
```
Открыть в браузере: `http://localhost:8000` (Swagger UI документация: `http://localhost:8000/docs`).

Сервер написан строго на стандартной библиотеке Python без сторонних зависимостей и сразу раздает предсобранный клиентский SPA. Подробная инструкция к АРМ - в [`arm/README.md`](arm/README.md).

### Опциональный запуск в Docker:
```bash
docker compose up --build
```
Интерфейс доступен по адресу: `http://localhost:8000`.
