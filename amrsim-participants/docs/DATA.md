# Описание данных. Кейс "Безопасный маршрут"

Симулятор amr-sim 0.2, схема сценария amr-1.0. Документ описывает состав данных, структуру сценария, что получает контроллер, по каким правилам работают модель мира и датчики, как считаются показатели и в каком виде выгружаются результаты. Все числа синтетические и не описывают реальную платформу.

## 1. Состав данных

| Что | Где |
| --- | --- |
| Симулятор (Python-пакет) | amrsim/ |
| Открытые сценарии | scenarios/*.json |
| Базовый контроллер | baseline/controller.py |
| Образцы лога и отчета | samples/ |
| Описание данных, инструкция | docs/DATA.md, docs/README.md |

Открытые сценарии:

| Файл | Маршрут | Что проверяет |
| --- | --- | --- |
| 01_clear | склад, цех A, склад | ясная погода, ГНСС на всем маршруте, два внимательных пешехода |
| 02_gnss_shadow | склад, цех B | тень ГНСС вдоль стены высокого корпуса (прямой участок 120 м) и под навесом: последние 143 м до дока без ГНСС |
| 03_fog_snow | цех A, склад, цех A | снег весь прогон, две полосы тумана, пропадание ГНСС внутри первой, невнимательный пешеход в тумане |
| 04_busy_yard | склад, цех A, склад | шесть пешеходов (два невнимательных), контейнер не на карте, оставленный поддон |
| 01e_clear_easy, 02e_gnss_shadow_easy | как 01 и 02 | учебные: в obs есть detections |

Скрытые сценарии строятся на той же площадке генератором организаторов: меняется тень ГНСС (вдоль высокого корпуса 120-135 м, всегда смыкается с навесом у цеха B; на маршрутах только по двору, склад и цех A, вместо нее тень на северной дороге до дока цеха A, по маршруту примерно 76-126 м), место и момент оставленного предмета, число и доля невнимательных пешеходов, окно пропадания ГНСС, туман, снег, 1-2 расхождения карты (минимум одно у маршрута), набор и порядок миссий (один из шести наборов плеч по точкам склад, цех A, цех B и зарядная станция, поэтому в скрытом сценарии миссия может идти и к зарядной станции; самое короткое плечо 39,6 м). Сценарий допускается, только если оракул (раздел 4) набирает больше 85 и базовый контроллер без истинной позы не проходит его легко. В скрытых сценариях detections нет.

## 2. Структура сценария (amr-1.0)

Файл JSON в кодировке UTF-8. Система координат: x на восток, y на север, метры; углы в радианах против часовой стрелки от оси x. Шаг модели 0,1 с.

| Поле | Тип | Смысл |
| --- | --- | --- |
| schema | строка | "amr-1.0" |
| name, description | строки | имя и описание |
| dt | число | 0.1, другое не поддерживается |
| duration_s | число | предел модельного времени, с |
| hidden | логическое | скрытый сценарий |
| provide_detections | логическое | учебный режим: detections в obs |
| weather.snow | логическое | снег на весь прогон |
| map | объект | карта (2.1); контроллер получает ее целиком |
| map_patches | список | расхождения карты и мира (2.2); контроллер их не получает |
| start | {x, y, theta} | начальная поза; контроллер получает ее списком [x, y, theta] в initial_pose |
| missions | список | задания (2.4) |
| pedestrians | список | пешеходы (2.3, 5.3); контроллер их не получает |
| events | список | события (2.3, 5.4); контроллер их не получает |

### 2.1. Карта map

| Поле | Содержимое |
| --- | --- |
| frame, bounds | описание системы координат; прямоугольник площадки [x0, y0, x1, y1] |
| drivable | список многоугольников проездов (ширина дорог 5 м); платформа должна оставаться центром внутри них |
| buildings | список {id, polygon}: здания, стены доков, столбы навеса; стены отражают лидар |
| points | точки warehouse, shop_a, shop_b, charger: {x, y, heading, tol}. heading это направление платформы, стоящей в доке лицом к стене; tol допуск остановки, 0.2 м |
| zones | список {id, type, polygon}: gnss_shadow (спутник недоступен), speed_limit (с полем v_max), forbidden (въезд запрещен), people_area (здесь ходят люди) |
| gates, crossing | ворота и пересечение с автодорогой: поля есть в схеме, в версии 0.2 поведение не моделируется |

Площадка около 250 x 200 м. Точки доставки стоят в доковых карманах шириной 5 м: стена перед платформой в 1,5 м от точки, боковые стенки в 2,5 м.

### 2.2. Расхождения карты map_patches

Список {id, op, polygon}. op = "add": в мире появляется препятствие polygon (новый забор, контейнер), на карте его нет. op = "remove": здания с этим id нет в мире (снесенный навес), а на карте оно есть. Лидар и столкновения работают по миру, контроллер знает только карту.

### 2.3. Пешеходы pedestrians и события events

| Поле пешехода | Смысл |
| --- | --- |
| id | строка, уникальна |
| waypoints | путевые точки [[x, y], ...], не меньше одной |
| speed | скорость, м/с (схема допускает 0,1-3,0; в сценариях 0,8-1,5) |
| inattentive | не останавливается перед движущейся платформой; по умолчанию false |
| loop | true (по умолчанию): по кругу; false: исчезает в последней точке |
| t_start | время появления, с; по умолчанию 0 |

События: {"type": "object_dropped", "t", "x", "y", "r"}, {"type": "gnss_outage", "t1", "t2"}, {"type": "fog_bank", "t1", "t2"}; смысл в разделе 5.4.

### 2.4. Миссии missions

| Поле | Смысл |
| --- | --- |
| id | m1, m2, ... |
| from, to | имена точек |
| deadline_s | дедлайн от начала миссии, с: длина reference_path / 1,39 x 1,6 |
| reference_path | эталонный путь [[x, y], ...]: кратчайший путь по drivable с отступом от стен, от дока from до дока to |
| reference_length_m | длина reference_path, м (справочно; счет берет длину из самого пути) |

Миссии выполняются по порядку. Следующая начинается сразу после закрытия предыдущей (прибытие или дедлайн). Прогон заканчивается, когда закрыты все миссии или истекло duration_s.

## 3. Интерфейс контроллера

Файл controller.py с классом Controller:

```python
class Controller:
    def __init__(self, map_, config, initial_pose):
        ...
    def step(self, obs):
        return {"v": 0.5, "w": 0.0, "status": "moving", "pose_est": [x, y, theta], "note": ""}
```

| Поле ответа | Обязательно | Смысл |
| --- | --- | --- |
| v | да | скорость, м/с; обрезается до [-0,5; 1,39] |
| w | да | угловая скорость, рад/с; обрезается до [-1; 1] |
| status | нет (moving) | moving, arrived, waiting, lost, estop |
| pose_est | нет | оценка позы [x, y, theta]; отсутствие считается большой ошибкой |
| note | нет | строка до 200 символов, попадает в лог |

v или w не число, неизвестный status, исключение в step: прогон останавливается с коротким сообщением "controller error at t=...: ... (controller.py:строка)" и не засчитывается. Печать (print) уходит в stderr, последние строки попадают в отчет (controller_stderr_tail).

status = "estop" включает аварийное торможение 2,5 м/с2. status = "arrived", удерживаемый 1 с (10 тиков подряд), закрывает текущую миссию (раздел 6.1).

### 3.1. Параметры config

Одинаковы во всех сценариях. Погода, события, seed и имя сценария в config не входят.

| Раздел | Параметры |
| --- | --- |
| dt | 0.1 |
| robot | radius 0.9; v_min -0.5; v_max 1.39; w_max 1.0; accel 0.5; decel 1.2; estop_decel 2.5 |
| lidar | beams 360; angle_min_deg 0; angle_increment_deg 1; max_range 20; sigma 0.03; fog_max_range 6; fog_dropout 0.1; snow_false_rate 0.03; snow_false_range [0.3, 3.0] |
| odom | scale_error_abs_range [0.01, 0.04]; sigma_rel 0.02; sigma_lat_rel 0.005; heading_rw_deg_per_sqrt_min 0.5; snow_multiplier 3 |
| imu | yaw_rate_sigma 0.01; yaw_rate_bias_sigma 0.0002; heading_sigma 0.002; heading_rw_deg_per_sqrt_min 0.3 |
| gnss | bias_tau_s 30; bias_sigma 0.25; white_sigma 0.3; jump_interval_s [60, 120]; jump_size_m [3, 8]; jump_duration_s [2, 5] |
| pedestrian | radius 0.3 |
| mission | arrival_hold_s 1.0; pickup_radius 2.0 |

### 3.2. Наблюдение obs

| Поле | Содержимое |
| --- | --- |
| t | модельное время, с |
| lidar.ranges | 360 дальностей, м; луч k направлен под углом heading + k градусов (k = 0 вперед, против часовой); NaN, если отражения нет |
| odom | dx, dy, dtheta: перемещение колес за прошлый тик в системе платформы на начало тика |
| imu | yaw_rate (рад/с), heading (рад, с уходом) |
| gnss | x, y, valid, hdop; при valid = false поля x, y, hdop равны null |
| mission | текущая миссия: id, index, count, from, to, goal [x, y, heading], tol, t_start, deadline_s, reference_path; null после последней |
| detections | только при provide_detections: список {class: person или object, x, y, vx, vy}; x, y: положение относительно платформы в ее осях (x вперед, y влево); vx, vy: скорость объекта относительно земли, повернутая в оси платформы (скорость самой платформы не вычитается); объекты не дальше 20 м (6 м в тумане), без учета заслонения; шум СКО 0,1 |

В obs нет истинной позы, пешеходов (кроме detections), расхождений карты, событий, seed, имени сценария.

### 3.3. Изоляция

Контроллер работает в отдельном процессе. Обмен строками JSON через stdin и stdout; рабочая папка процесса пустая временная, sys.argv пустой, переменные окружения с путем сценария и seed не передаются. Контроллер может читать файлы своей папки и писать только во временную рабочую папку (она удаляется после прогона); чтение других файлов, запуск процессов и сеть блокируются и записываются в отчет (sandbox_violations). Отладочный вывод: print в stderr.

Разрешенные импорты: стандартная библиотека и numpy. Запрещены amrsim, gc, inspect, ctypes, multiprocessing, threading, concurrent, доступ к кадрам интерпретатора (sys._getframe и подобное). Проверка: python -m amrsim check <папка>. Нарушение означает 0 за кейс. Предел реального времени 10 минут на сценарий; превышение означает, что сценарий не засчитан. На время одного шага ограничения нет; среднее и максимальное время шага пишутся в отчет.

## 4. Режим оракула

python -m amrsim run ... --cheat передает истинную позу через отдельный канал: перед каждым step вызывается Controller.set_truth(pose), если такой метод есть. В obs истины нет и в этом режиме. Оракул это baseline с истинной позой; скрытый сценарий допускается к зачету, только если оракул набирает больше 85. Отчет оракула помечен cheat = true и в рейтинг не идет.

## 5. Модель мира и датчиков (правила расчета)

### 5.1. Платформа

Дифференциальный привод, круг радиуса 0,9 м. Скорость меняется не быстрее 0,5 м/с2 при разгоне, 1,2 м/с2 при торможении (путь торможения с 1,39 м/с около 0,80 м), 2,5 м/с2 при estop. Угловая скорость принимается сразу. Если следующее положение пересекает препятствие или пешехода, платформа остается на месте (истинная скорость 0), а колеса продолжают вращаться как по команде: одометрия контакт не показывает.

### 5.2. Датчики

| Датчик | Модель |
| --- | --- |
| Лидар | 360 лучей по 1 градусу, дальность 20 м, белый шум 0,03 м. Туман (fog_bank): дальность 6 м, 10% лучей NaN. Снег: 3% лучей дают ложный возврат 0,3-3 м |
| Одометрия | масштаб на прогон: 1-4% (знак случайный), контроллеру неизвестен; белый шум 2% пройденного вдоль и 0,5% поперек; курс: случайное блуждание 0,5 градуса за корень минуты, пока колеса крутятся. Снег: шум x3 |
| ИНС | yaw_rate: истинная + постоянное смещение на прогон (СКО 0,0002 рад/с) + шум 0,01 рад/с; heading: истинный + уход (случайное блуждание 0,3 градуса за корень минуты) + шум 0,002 рад |
| ГНСС | смещение по каждой оси: процесс с временем корреляции 30 с и СКО 0,25 м (амплитуда около 0,5 м), плюс белый шум 0,3 м. Раз в 60-120 с скачок 3-8 м на 2-5 с; hdop иногда растет при скачке, но не всегда. В зонах gnss_shadow и в окна gnss_outage valid = false |

Шум коррелированный намеренно: усреднение белого шума не дает точную позу, масштаб одометрии не выводится из первых метров.

### 5.3. Пешеходы

Круги радиуса 0,3 м, идут по путевым точкам со скоростью 0,8-1,5 м/с; loop = true: по кругу, иначе исчезают в последней точке; t_start: время появления (не ближе 4 м от движущейся платформы и 1,5 м от стоящей). Внимательный пешеход останавливается, пока движущаяся платформа (|v| > 0,05) ближе 4 м впереди него. Невнимательный не останавливается. Любой пешеход обходит стоящую платформу, держа центр не ближе 1,5 м от ее центра; если его путевая точка внутри этого круга, он ждет не дольше 2 с и идет к следующей.

### 5.4. События

| Событие | Поля | Действие |
| --- | --- | --- |
| object_dropped | t, x, y, r | с момента t в мире круглый предмет радиуса r (поддон), на карте его нет; появление откладывается, пока место занято или платформа не успеет остановиться |
| gnss_outage | t1, t2 | в [t1, t2) ГНСС недоступен везде |
| fog_bank | t1, t2 | в [t1, t2) туман для лидара |

## 6. Показатели

Итог сценария = сумма блоков, ограниченная диапазоном 0-100. Блоки могут уходить в минус. Блоки безопасности, правил движения и честности оценки позы начисляются только в сценарии, где доставлена хотя бы одна миссия: без доставок итог сценария 0, а эти блоки остаются в отчете со своими значениями и помечены в поле not_counted_blocks. Все расстояния до людей и предметов это зазоры между кругами (от края платформы до края человека). Эпизод объединяет тики нарушения, между которыми меньше 2 с без нарушения (гистерезис 2 с).

| Блок (ключ в отчете) | Макс | Правило |
| --- | --- | --- |
| Перевозки (delivery) | 40 | 40 x доля доставленных миссий |
| Эффективность (efficiency) | 15 | 15 x среднее по миссиям: для доставленной min(1, max(0, 2 - t/T)), T = длина эталона / 1,39 x 1,25; для недоставленной 0 |
| Безопасность (safety) | 25 | человек ближе 3 м при |v| > 0,28: -2 за секунду; человек ближе 0,5 м при |v| > 0: -10 за эпизод; контакт со стоящей платформой: -10 за эпизод |
| Правила движения (rules) | 10 | центр вне drivable: -3 за эпизод; в зоне forbidden: -5 за эпизод; |v| > v_max зоны + 0,05: -2 за эпизод |
| Честность оценки позы (pose) | 10 | ошибка pose_est больше 1 м при |v| > 0,05 дольше 5 с: -3 за эпизод (status = lost с v = 0 не считается движением); status не moving при |v| > 0,05 дольше 1 с: -2 за эпизод; estop, когда ближе 1,5 м нет ничего: -1 за эпизод |
| Контакт с пешеходом (fatal) | обнуление | если |v| > 0,1 в момент контакта или в течение 1 с до него: итог сценария 0 |
| Контакт с предметом или зданием (collisions) | -30 | за эпизод |
| Нет ни одной доставки | итог 0 | блоки безопасности, правил и честности не начисляются (в отчете поле not_counted_blocks), итог сценария 0 |

### 6.1. Доставка

Миссия доставлена, если одновременно:
1. контроллер 10 тиков подряд (1 с) сообщал status = "arrived";
2. во всех этих 10 тиках истинное расстояние до точки to меньше tol (0,2 м);
3. эти 10 тиков закончились не позже deadline_s от начала миссии;
4. за время миссии до этого платформа побывала ближе 2 м к точке from (забор груза).

Время миссии t для эффективности: от начала миссии до первого из 10 тиков arrived. Если arrived удерживается, а условия 2 или 4 не выполнены, миссия закрывается как не доставленная и начинается следующая.

### 6.2. Итог кейса

Среднее по всем прогонам команды, скрытые сценарии с весом 2. Прогон, не засчитанный из-за ошибки контроллера или предела времени, дает 0. Нарушение amrsim check дает 0 за кейс. Официальный счет рассчитывается на инфраструктуре проверки на отдельной копии amrsim.

## 7. Формат выгрузки

Прогон пишет два файла: лог JSONL (ключ --log) и отчет JSON (ключ --report). Рабочее место оператора (обязательная часть кейса, критерий О3 на 15 баллов) строится именно на этих файлах: лог дает карту, траекторию, пешеходов и события по тикам, отчет дает счет, миссии и эпизоды штрафов. Чтобы начать делать рабочее место до того, как готов свой контроллер, в архиве участников лежит папка samples/ с готовыми файлами базового контроллера:

| Файл | Что это |
| --- | --- |
| samples/01_clear.jsonl, samples/01_clear.json | лог и отчет прогона baseline на 01_clear, seed 7 |
| samples/04_busy_yard.jsonl, samples/04_busy_yard.json | то же на 04_busy_yard (шесть пешеходов, контейнер не на карте, поддон) |

Те же файлы получаются командой:

```
python -m amrsim run scenarios/01_clear.json --controller baseline/controller.py --seed 7 --report samples/01_clear.json --log samples/01_clear.jsonl
```

### 7.1. Лог (--log, JSONL)

Одна запись JSON на строку, по порядку времени. Типы записей: header (первая строка), tick (на каждый шаг 0,1 с), mission (при закрытии миссии), end (последняя строка).

**header**: что и чем прогнали, плюс полная карта мира для отрисовки.

| Поле | Смысл |
| --- | --- |
| type | "header" |
| schema | версия схемы сценария, "amr-1.0" |
| amrsim | версия пакета |
| package_hash | хеш пакета amrsim для проверки неизменности симулятора |
| scenario | имя сценария |
| scenario_sha | хеш файла сценария |
| seed | seed прогона; salted: true, если seed смешан с солью официального прогона |

| Поле | Смысл |
| --- | --- |
| type | "tick" |
| t | модельное время, с |

| v, w | истинная скорость, м/с, и угловая скорость, рад/с, на начало тика |
| cv, cw | что запросил контроллер: v и w до ограничений |
| st | статус контроллера: moving, arrived, waiting, lost, estop |
| pe | оценка позы контроллера [x, y, theta] или null |
| nt | поле note контроллера, если оно не пустое: это причина остановки или замедления, которую рабочее место показывает рядом со статусом st. Пишет его контроллер команды, поэтому свой контроллер должен туда писать (baseline пишет person near и too close: в samples/04_busy_yard.jsonl nt есть в 74 тиках из 3717, в samples/01_clear.jsonl в 1 из 3287) |
| m | id текущей миссии или null |
| drv | 1, если центр платформы внутри drivable |
| fbd | 1, если центр в зоне forbidden |
| vmax | предел скорости зоны, м/с, или null |
| hum | зазор до ближайшего человека, м (от края платформы до края человека), null, если людей нет |
| obj | зазор до ближайшего препятствия любого вида, м, или null, если ближе 3 м от края платформы нет ни зданий, ни предметов, а людей в мире сейчас нет (в samples/01_clear.jsonl так в 76 тиках, t от 7,5 до 15,0) |
| coll | 1, если в этом тике платформа уперлась в предмет или здание |
| cont | 1, если в этом тике был контакт с пешеходом |
| peds | позиции идущих в этот момент пешеходов [[x, y], ...] в порядке сценария, без id; ключа в записи нет, пока не идет ни один (пешеход появляется в t_start, раздел 2.3, и исчезает в последней точке при loop false); в samples/01_clear.jsonl ключа нет с t=0,0 до t=15,0, первая запись с peds t=15,1. Список пересобирается каждый тик из идущих сейчас, поэтому номер в списке не закреплен за человеком: когда кто-то появляется или заканчивает путь, остальные сдвигаются. Для рабочего места оператора сопоставлять пешеходов между тиками по близости координат или брать их из файла сценария (раздел 2.3) |

### 7.3. Таблица batch (CSV)

python -m amrsim batch teams/ scenarios/ hidden/scenarios/ --seeds 1,2,3 --out table.csv (одна или несколько папок или файлов сценариев) пишет строку на каждый прогон: team, scenario, hidden, seed, counted, total, deliveries (сколько миссий доставлено; 0 означает, что пассивные блоки не начислялись), блоки, fatal, end_reason, error, wall_s, step_mean_ms, step_max_ms, sandbox_violations, check. Сводка по командам: table_summary.csv (check, open_mean, hidden_mean, case_score). check: OK, FAIL (нарушение, 0 за кейс), MISSING (нет controller.py в папке команды, 0), ERROR (проверка упала, разбор вручную). Строки прогонов пишутся по мере готовности; прогон, упавший не по вине контроллера, получает end_reason error, и команда batch завершается с кодом 1.

## 8. Проверка входа

| Проверка | Команда | Результат |
| --- | --- | --- |
| окружение | python -m amrsim doctor | версии Python и numpy, запись в out/; последняя строка doctor: OK |
| сценарий | любая команда с файлом сценария | ошибка с местом: "scenarios/x.json: missions[0].reference_path[3]: expected [x, y]" |
| правила контроллера | python -m amrsim check team/ | VIOLATION (0 за кейс), ERROR (не запустится), WARNING (для ручной проверки) |
| расчет счета | python -m amrsim probe-scoring | известный лог дает известный счет по блокам |
| детерминизм | python -m amrsim probe-determinism | два прогона дают одинаковые отчет и лог |
| быстрый прогон | python -m amrsim smoke | baseline на 01 быстрее 20 с |

Коды выхода: 0 успех; 1 ошибка проверки (check нашел нарушение, doctor, smoke, пробы, batch с упавшими не по вине контроллера прогонами); 2 ошибка ввода (нет файла или папки, неверный JSON, неверные аргументы, render без matplotlib); 3 ошибка контроллера; 4 превышен предел реального времени. Трассировки не печатаются (ключ --debug их покажет): обычно одна строка error: ...; при неверных аргументах перед ней строка usage; render без matplotlib печатает подсказку, как построить график из JSONL.

Детерминизм: одинаковые сценарий, seed и контроллер дают одинаковый лог на одной машине (если контроллер сам детерминирован). Между машинами допуск 0,5 балла.

## 9. Формат сдачи и правила

Дословно из постановки задачи (docs/CASE.md, раздел "Ожидаемый результат"):

Репозиторий команды в GitVerse: controller.py и соседние модули; requirements.txt (только numpy); APPROACH.md на 15-25 строк (локализация, следование, безопасность, что не сделано); папка results с отчетами score по открытым сценариям; папка arm с рабочим местом оператора и инструкцией запуска (обязательная часть); презентация до 12 слайдов. Защита до 5 минут: подход, результаты на сценариях, демонстрация рабочего места оператора, поведение в сложных условиях, ограничения.

```
team_<name>/
  controller.py       # точка входа, может импортировать соседние модули
  requirements.txt    # только numpy
  APPROACH.md         # 15-25 строк: локализация, следование, безопасность, что не сделано
  results/            # отчеты score по открытым сценариям
  arm/                # рабочее место оператора и README запуска (обязательно)
  tests/              # свои автотесты контроллера (по желанию, критерий Т5)
  scenarios/          # свои сценарии проверки (по желанию, критерий О4)
  presentation.pdf    # до 12 слайдов
```

Правила прогона и оценки:

- Официальные прогоны выполняются на инфраструктуре проверки на отдельной копии симулятора. В каждом отчете есть хеш пакета (package_hash) и хеш файла сценария; результаты, посчитанные на измененном симуляторе, не учитываются. Папка results используется как справочная; официальным считается только счет официального прогона.
- Обход изоляции контроллера (доступ к истинному положению, сценарию, seed или файлам симулятора) означает 0 за кейс. Заблокированные попытки видны экспертам в поле sandbox_violations отчета и в столбце sandbox_violations таблицы batch.
- Нарушение python -m amrsim check (запрещенные импорты, лишние зависимости, доступ к кадрам интерпретатора) означает 0 за кейс.
- Прогон, не засчитанный из-за ошибки контроллера или превышения предела реального времени (10 минут на сценарий), дает 0 по этому сценарию.
- Сценарий, в котором не выполнена ни одна перевозка, дает 0: блоки безопасности, правил движения и честности оценки позы начисляются только при хотя бы одной доставке (в отчете они остаются видны с пометкой not_counted).
- Критерии оценки и их баллы: docs/CRITERIA.md.
