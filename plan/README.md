# Бэкенд-план. Безопасный маршрут

Контроллер платформы для кейса «Безопасный маршрут» (amr-sim 0.2, схема amr-1.0). Рабочее место оператора (критерий О3, 15 баллов) в этот план не входит. Контракт с ним: поля `status`, `pose_est` и `note`.

Победа сидит в позе. Скрытые сценарии в `case_score` идут с весом 2 и дают критерий Т1 (0-25). Baseline доезжает 01 и 03, почти всегда 04, и проваливает 02: 143 м без ГНСС, одометрия уезжает, лидар по стенам в позу не входит. Скрытый сценарий пускают в зачет, только если оракул (baseline + истина) берет больше 85, а baseline без истины проходит его плохо. Дыра одна: локализация. Безопасность baseline уже близка к потолку. Ее надо сохранить и дожать.

## Где лежат баллы бэкенда

| Критерий | Баллы | Что закрывает контроллер |
| --- | ---: | --- |
| Т1. Скрытые сценарии | 25 | доставки, ноль наездов, зоны, скорость, `lost` при потере ориентации |
| Т2. Открытые 01-04 | 10 | все миссии, `counted`, нет наезда; 02 без спутника; 03 и 04 без столкновений |
| Т4. Честность позы | 5 | своя `pose_est`, не копия ГНСС; `lost` согласован с остановкой; `estop` только с объектом рядом |
| Т5. Архитектура | 5 | модули локализации, планирования, следования, безопасности; тесты; без мертвого кода |
| О1. Обоснование | 10 | текст `APPROACH.md` совпадает с кодом |
| О2. Демо сложных условий | 10 | тень, туман, пешеход, `lost`; эпизоды объясняются полем `note` |
| О4. Дополнительно | 10 | боковой сдвиг, переплан, детектор расхождения карты, свои сценарии, тесты |

`python -m amrsim check` с VIOLATION или обход изоляции обнуляют кейс целиком. Прогон с ошибкой контроллера или wall > 600 с дает 0 за сценарий. Ноль доставок дает 0 за сценарий: блоки safety, rules и pose в зачет не идут.

## Архитектура

Только стандартная библиотека и numpy. `scipy`, `numba`, потоки, `inspect`, импорт `amrsim` дают VIOLATION.

```
controller.py   # Controller.__init__ / step / set_truth
geom.py         # отрезки, raycast, point-to-segment, полигоны, углы
localize.py     # предикт, скан-матч, ГНСС, масштаб, ориентиры, док, lost
perceive.py     # снег, кластеры, треки, класс, туман, патчи карты
route.py        # эталон, боковой сдвиг, A*
safety.py       # лимиты скорости, статусы, note
```

Порядок `step`:

1. Предикт позы по одометрии и ИНС.
2. Скан-матч, гейт ГНСС, углы стен, dock-snap.
3. Кластеры и треки в кадре чистой одометрии.
4. Новая миссия: запомнить `reference_path`, сбросить `arrived`.
5. Статический кластер в трубке пути: сдвиг или A*.
6. Pure pursuit, затем лимит зоны, затем лимит безопасности.
7. Статус по скорости одометрии, не по команде.
8. `pose_est` - среднее фильтра. Сырой ГНСС в `pose_est` не копировать.

`set_truth` оставить для локального `--cheat`. В формулах позы не использовать.

## Порядок сборки

Каждый шаг обязан оставить сценарий 01 не хуже baseline. Жадный лидар на пешеходе типично ломает 01 при починке 02.

1. Каркас и перенос baseline. Снять цифры 01-04 на seed 7.
2. Предикт ИНС и гейт ГНСС.
3. Скан-матч стен. Цель: 02 доезжает до дока B.
4. Углы, столбы, масштаб. 02 на наборе seed, ошибка позы на прямой меньше 1 м.
5. Dock-snap на четыре точки, включая зарядную.
6. Статус `moving`, пока платформа реально катится.
7. Лимиты зазоров. Сценарий 03 без fatal и без `person_near_fast`.
8. Детектор упора колес.
9. Боковой сдвиг у предмета в 2 м от оси.
10. A*, если сдвиг не влезает в проезд.
11. Снесенная стена выпадает из матчера.
12. `lost` и поиск позы.
13. Туман и снег. Сценарий 03 укладывается в дедлайн.
14. Пакет seed на 01-04. Чинить худший эпизод.
15. `APPROACH.md`, `results/`, тесты.

Детали приемки: [05-sborka-i-priemka.md](05-sborka-i-priemka.md).
